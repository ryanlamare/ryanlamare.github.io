# Teaching hub — working memo

**Status: built (2026-08-17).** `/teaching/` is live: affiliation → course →
weeks, generated by `build_teaching.py` from `teaching_data.py`. How it works
is documented in `CLAUDE.md`; this memo keeps the decisions and what is still
parked.

---

## What was built

- **`teaching/illinois/ler565/`** — the six weeks moved under an affiliation
  level (`git mv`, so history follows). Nothing inside the decks needed
  rewriting: they had no links out of their own folder.
- **Four generated index pages** — the hub, one per affiliation, one per course
  with decks. The hub lists each affiliation *with its courses inline*, so a
  course is one click from the front page even though the URLs are three deep.
- **A homepage link**, understated: one line under MG478 in the Teaching
  section, `Course materials — lecture slides and live sessions ›`.
- **`noindex` on all 24 pages** under `teaching/`, and a `robots.txt`.

## Decisions, and the reasoning worth keeping

- **Top level is affiliation, not course.** Keeping the three bodies of work
  separate is the organising constraint, so it belongs in the URL. `illinois`
  over `uiuc` — more readable.
- **No explanatory prose about the separation.** The structure does the work;
  writing "not an LSE course" would be defensive.
- **Lecture slides and live sessions only.** Games, quizzes, brackets,
  shortlist rounds and the Titan Wars memo are never listed.
- **The exec programme is unlisted, and did not move.** No entry in
  `teaching_data.py` is what keeps it off the hub. Moving it would have bought
  tidiness at the cost of breaking the two absolute links inside it and any URL
  already sent to the client — no gain for something nobody browses to.
- **Generated, not hand-written.** The builder reads each deck's `<title>`, so
  a new week appears everywhere the moment the folder exists.
- **`robots.txt` does not block `/teaching/`, on purpose.** This reverses what
  this memo originally proposed. A crawler has to fetch a page to see its
  `noindex`; disallowing the path would prevent that and leave the URLs
  eligible to appear as bare links — the opposite of the intent. `noindex`
  alone is the directive that actually keeps a page out of the index, and the
  homepage now links to `/teaching/`, so it will be crawled. The reasoning is
  written into `robots.txt` itself.
- **No redirect stubs at the old `/teaching/ler565/…` URLs.** The class ended
  w/c 2026-08-09; those links are spent. Revisit only if students still hold
  them.

## The caveat that still matters

`noindex` stops search engines; it does **not** stop access. Anyone with a URL
can open anything.

More to the point: **while the site repo is public, every deck's source is on
GitHub and GitHub is itself indexed.** So none of the above hides the Titan Wars
memo from someone searching GitHub. If "not searchable" is ever a real
requirement rather than a preference, the repo going private is the change that
delivers it — Pages needs a paid plan (Pro ~$4/mo) to serve from a private repo.
Still open, and still the only lever that would change the answer.

## Later: revealable games

Wanted: activities visible each week but greyed out, unlocked ahead of class or
live in the session. Replacing Canvas PDFs with portable materials Ryan owns.
Three ways to do it, in increasing order of cost and strength:

1. **Cosmetic lock** — tile greyed, becomes clickable at a timestamp baked into
   the page. ~20 lines, no infrastructure, works offline. But the link sits in
   the page source and the clock is the student's, so it discourages rather than
   prevents. Fine for "don't spoil it", useless for genuinely secret content.
2. **Scheduled publish** — the game file is genuinely absent from the site until
   a scheduled GitHub Action publishes it. Nothing to find early because nothing
   is there. Uses infrastructure that already exists (the CV Action), costs
   nothing, and needs no live intervention. **Best value; start here.**
3. **Live instructor switch** — flip a game open mid-session from a phone.
   Requires the realtime service (see below). The right moment for this is the
   MG478 rebuild, where it replaces Mentimeter.

Note the interaction: with a **private** repo, option 1 becomes meaningfully
stronger, because unlisted content is no longer discoverable through GitHub.

Where this would land in the hub: a third row in each week, beside Lecture and
Live session — which is a change to `week_block()` in `build_teaching.py` and a
decision about which folders count as listable, nothing more.

## Also parked: live multiplayer games

For the MG478 rebuild. GitHub Pages is static and cannot run a backend, so
anything where students' devices see each other's choices needs external state.
Pavilion's `relay/` now solves exactly this problem on Cloudflare — read that
before reaching for PartyKit, Firebase or Supabase. Design rules agreed: room
codes not logins, no personal data, and an offline fallback so a wifi failure
degrades to the pairs-on-one-laptop version rather than killing the session.
